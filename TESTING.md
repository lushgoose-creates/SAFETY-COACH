# Pre-demo manual testing checklist

Run all ten tests with the exact phone, Wi-Fi/tunnel, API account, and browser you will use for the presentation. Start with `npm run clear-demo` if real-looking results should be empty.

- [ ] **1. Scan the correct machine QR** — Set `PUBLIC_BASE_URL`, restart, print/open `/qr`, and scan each code with a phone. Confirm the lathe code opens only `/m/lathe`, the drill code only `/m/drill-press`, the machine name is prominent, and the layout is readable at 375px width. Open `/qr?lang=en` and confirm English codes include `?lang=en`; on a student page switch Chinese/English, reload, and confirm the selected language persists.
- [ ] **2. Ask an in-SOP question** — On the lathe page ask `启动前卡盘钥匙要放在哪里？`. Confirm a short Chinese answer says to remove it and cites `【规则8】`. In English ask `What should I do with the chuck key before starting?` and confirm an English answer cites `[Rule 8]`. Verify no other machine's rules are used.
- [ ] **3. Ask an out-of-SOP question** — Ask `这台设备的采购价格是多少？` or another question absent from the SOP. Confirm the app does not invent an answer, says the SOP does not clearly cover it, directs the student to the instructor, and adds the question to the dashboard escalation list.
- [ ] **4. Ask an unsafe question** — Ask `为了清理方便，可以戴着手套靠近旋转主轴吗？`. Confirm the answer clearly says `不可以`, explains the entanglement danger, and cites the no-gloves rule. Never perform the action as a physical test.
- [ ] **5. Fail the quiz** — Enter a test name/ID and deliberately select at least one wrong answer. Confirm all three must be answered, the red result appears, every relevant `规则N` is listed for review, and the failed attempt appears on `/admin`. Retry and confirm retries are separate records.
- [ ] **6. Pass the quiz** — Answer all three correctly. Confirm the green Chinese or English pass card shows name, student ID, machine, and current timestamp. Reload and confirm name/ID and the selected language are remembered by `localStorage` on that phone.
- [ ] **7. Verify dashboard updates** — Keep `/admin` open while another phone submits a quiz and asks a question. Within 10 seconds, confirm recent attempts, pass rate, common questions, difficult questions, and unanswered lists update as applicable. Test **重新生成题目** and confirm the student still receives three questions without a `correctIndex` field.
- [ ] **8. Export CSV** — Export from both `/admin` and `/admin?lang=en`, open each file in Excel, and verify the selected language is used for headers, machine names, pass/fail, and DEMO/real labels while name/ID and timestamps remain correct. Run `npm run seed-demo`, verify 12 labeled DEMO rows, then `npm run clear-demo` and verify only DEMO attempts disappear.
- [ ] **9. Verify AI failure behavior** — Temporarily set an invalid `API_KEY` (or disconnect the API network) and restart. Confirm Chinese and English briefing/quiz fallbacks still work, Q&A shows a friendly connection error and retry action in the selected language, the failed question is escalated, and no fake AI answer is presented. Restore the key/network, restart, and verify recovery.
- [ ] **10. Use two phones at once** — Open different machines on two phones, ask questions and submit quizzes concurrently. Confirm identities do not leak between browsers, attempts are saved separately, neither phone receives correct answers before submission, and the dashboard shows both. If using one tunnel, also confirm the 20-question/IP/minute limit does not interrupt your scripted demo.

Final live-demo check: restore the valid `.env`, use a strong admin password, clear DEMO attempts, pre-cache both machines' content in each language you will demonstrate, keep the server and tunnel terminals open, carry a charger/hotspot backup, and do not edit SOPs during the presentation.
